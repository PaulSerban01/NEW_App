Foundation

Token architecture

Three tiers — primitive, semantic, component — mirror the Figma Variables model. Flipping a theme rebinds semantic tokens, and every component follows automatically.

The three tiers

Tier 1

Primitives

Raw palette values. Named by family and rung: --p-500, --n-200, --t-300, --danger-500. Never referenced by components.

Tier 2

Semantic

Intent aliases: --fg-default, --bg-surface, --accent-bg, --border-focus. These rebind per theme.

Tier 3

Component

Local variables scoped to a component. Read from semantic tokens only — never skip the middle layer.

Rebinding per theme

A semantic token changes value when the palette or mode flips. The component never knows.

/* Light × Teal */
--accent-bg:       var(--teal-700);   /* #00686A */
--fg-on-brand:     var(--n-0);

/* Dark × Teal */
--accent-bg:       var(--teal-400);   /* #23F7DD */
--fg-on-brand:     var(--teal-950);

Figma mapping

In Figma Variables, create a Palette mode with three values and a Mode mode with two. Primitive collections publish per palette; semantic collections read from them. Component libraries bind to semantic only.

One-to-one with CSS
The data-palette × data-mode combination on <html> maps directly to two Figma modes. Token names match exactly, so designers and engineers speak the same language.
